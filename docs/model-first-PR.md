# Model-first Rung: the model understands language, code never does

## What this changes

Every piece of code that read human text with regex, keywords, stopwords or substring checks is **deleted**, not kept as a fallback:
- request parsing in `understand.py`;
- the date parser;
- `HeuristicExplorer`;
- regex precedent mining;
- the regex fake model;
- the offline eval mode.

With `RUNG_MODEL` unset, `rung run` now refuses to run.

In their place:

- **Understanding:** one typed call, `understand_request`, then deterministic grounding in `rung/ground.py`.
  - People are matched against HR by exact work email, or by name tokens against the full name.
  - Anyone ambiguous is asked about, never guessed. Several people split into child runs, and nobody is dropped.
  - Dates must be ISO dates. Low confidence or disagreement with HR leads to a question; a date never defaults to today.
- **Variable steps:** code gathers the evidence: peer setups, mail with a trust flag taken from the sender's domain, chat, and the SOP. `propose_steps` (the model) proposes steps from it, and `rung/proposals.py` validates each one:
  - known app, entity and fields only;
  - the step must target the run's subject;
  - referenced values must exist (the channel must be in Chatter's channel list);
  - citations must point at evidence that was actually provided;
  - untrusted evidence never justifies a step;
  - written policy applies, and precedent may not authorise anything above reversible writes.
  - Every rejection becomes a flag in the report.
- **Explorer:** model-only. Code enforces what the model may do in the browser:
  - it may type only values the task supplied (passwords are generated by code);
  - it may select only options that match a supplied value;
  - checkbox values are parsed as true/false tokens;
  - navigation stays inside the app.
  - The goal check (`app.holds()`) runs after every action. Navigation hints come from verified past changes.
- **409 fix:** learned tools are demoted only on 404/405/410 or schema drift; 409/422 count as plain failures. Test in `tests/test_core.py`.
- **Replay:** `RUNG_MODEL=replay` matches prompts exactly, except that wall-clock times are masked in the matching key. An unrecorded prompt fails loudly.
- **Model calls:**
  - reasoning is set per call type, chosen by layer benchmarks (`eval/bench_*.py`);
  - a client-side limiter caps requests at 18/min (NIM allows 20);
  - code supplies a four-week calendar so the model looks weekdays up rather than computing them.
- **Eval:** six new cases (N1–N6) plus SOP drafting on the real model (C9). Results now list false successes first.
